# 📝 How to Add a Story

Just 3 steps:

1. Create a folder `NN-story-name/`
2. Write `config.json`
3. Run `story build`

---

## 📁 Directory Convention

Stories are folders at the repository root:

```text
my-stories-repo/
├── config.original.json      # Template for original stories (generated by story init)
├── config.fanfic.json        # Template for fan fiction (generated by story init)
├── story-template.md         # Handlebars template for story READMEs
├── story.config.json         # Repo-level config (custom types/statuses, generated by story init)
├── README.md                 # Auto-generated root index
├── assets/                   # Global material directory (covers, etc.)
│   └── sponsor/              # Dedicated directory for donation QR codes (created by story init)
│       ├── README.md         # Directory usage description
│       └── .gitkeep          # Keeps empty directory trackable by Git
│
└── 01-my-story/              # Story folder (NN- prefix required)
    ├── config.json           # Story metadata
    ├── text.md               # Full content (single file)
    ├── chapter-*.md          # Optional: split into chapter files
    ├── assets/               # Optional: images used in the story (or root assets/)
    └── README.md             # Auto-generated story page
```

> 💡 Root `assets/` is the global material directory (covers, etc.). `assets/sponsor/` is the dedicated directory for donation QR codes (see below).
>
> 💡 The `NN-` prefix is a sequence number with **at least two digits** (e.g. `01-`, `02-`, `100-`) that controls display order. **Duplicate numbers are not allowed** — they will trigger a warning during `story build`.

### 💰 Donation Support (Optional)

If you want to display a "☕ Support" section in the root README (where readers can tip you), place your payment QR code images in the `assets/sponsor/` directory:

```text
assets/
└── sponsor/           # Dedicated directory for donation QR codes (any filenames/quantity)
    ├── ali-pay.jpg
    └── wechat-pay.jpg
```

When `story build` detects images in `assets/sponsor/`, it automatically generates a collapsible "☕ Support" section in the root README. If the directory doesn't exist or is empty, the section is hidden.

**Note**: `assets/sponsor/` is a dedicated directory — do not put story images there. Story images belong in `assets/` or in each story folder's `assets/`.

### Sequence Number Rules

`story new "Title"` auto-assigns the next number as **current max + 1**:

```text
01-story-a
02-story-b
03-story-c
```

- Delete `02-story-b` then create a new story → you get `04-new-story` (the `02` slot is **not** reused)
- Delete `03-story-c` then create a new story → you get `03-new-story` (the trailing empty slot is reused)

**Why this design**: sequence numbers exist solely to control display order. This ensures links to existing stories (README, EPUB references) remain stable forever — deleting or adding stories never shifts existing numbers.

**Manual creation**: if creating folders by hand, `NN` must use **at least two digits** (e.g. `01-`, `05-`, `100-`). Single-digit prefixes (e.g. `5-`) are not recognized as story directories. Gaps in the sequence are fine (as long as numbers don't collide), but `story new` will not fill gaps.

## 📝 config.json Reference

```json
{
  "title": "Story Title",
  "type": "original", // "original" or "fanfic"
  "status": "ongoing", // "completed" or "ongoing"
  "isMultiChapter": false,
  "language": "zh", // "zh" or "en"
  "summary": "One-sentence summary of the story.",
  "created": "2026-08-14", // YYYY-MM-DD
  "author": "Author name", // Optional, for original stories (shown in EPUB export)
  "originalWork": "Original Work", // Required for fanfic
  "originalAuthor": "Author" // Required for fanfic
}
```

### Field Reference

| Field            | Required    | Type      | Description                                             |
| ---------------- | ----------- | --------- | ------------------------------------------------------- |
| `title`          | ✅          | `string`  | Story title                                             |
| `type`           | ✅          | `string`  | `"original"` or `"fanfic"`                              |
| `status`         | ✅          | `string`  | `"completed"` or `"ongoing"`                            |
| `isMultiChapter` | Optional    | `boolean` | Whether this is a multi-chapter story (default `false`) |
| `language`       | Optional    | `string`  | `"zh"` or `"en"`, determines README localization        |
| `summary`        | ✅          | `string`  | One-sentence summary of the story                       |
| `created`        | ✅          | `string`  | Creation date in `YYYY-MM-DD` format                    |
| `author`         | Optional    | `string`  | Author name (used for original stories, shown in EPUB)  |
| `originalWork`   | Fanfic only | `string`  | Original work name (required if fanfic)                 |
| `originalAuthor` | Fanfic only | `string`  | Original author (required if fanfic)                    |

### Validation Rules

- `title`, `type`, `status`, `summary`, `created` are required; missing fields cause a build error
- `type` must be `original` or `fanfic`
- `status` must be `completed` or `ongoing`
- `created` must match the `YYYY-MM-DD` format
- When `type` is `fanfic`, both `originalWork` and `originalAuthor` are required

## ✍️ Writing Styles

### Option 1: Single file `text.md`

Write directly in `text.md` — the simplest approach:

```markdown
# Chapter One

Body content...

# Chapter Two

Body content...
```

### Option 2: Multiple chapter files `chapter-*.md`

Split content into multiple chapter files:

```text
01-my-story/
├── config.json
├── chapter-1-opening.md
├── chapter-2-development.md
└── chapter-3-climax.md
```

When `text.md` does not exist, `story build` automatically merges all `chapter-*.md` files into a generated `text.md`.

---

## 🚀 Auto Generation

Run:

```bash
story build
```

This generates a `README.md` for each story and a root index `README.md`. If `text.md` is missing but `chapter-*.md` files exist, they will be merged and a `text.md` will be generated automatically.
