**A zero-deploy, Git-native content management CLI for Markdown.** Use simple directory conventions to manage stories/papers/notes/tutorials, auto-generate READMEs, export EPUB, bilingual (zh/en).

---

## ✨ Features

- **Simple directory convention** — content is a folder: `NN-name/` with `config.json` + `text.md`
- **Automatic README generation** — per-entry and root index READMEs (template-driven, customizable)
- **Series grouping & sorting** — `series` / `seriesOrder` control display order, insert anywhere without renumbering
- **Runtime validation** — config checks before building (required fields, enums, formats)
- **Bilingual support** — zh/en content with localized READMEs
- **Chapters + word counts** — auto-extract chapter titles and language-aware word counts
- **Multi-format export** — EPUB / HTML / TXT / JSON / Markdown, with `--stdout` pipe support
- **General-purpose content platform** — knowledge mode (paper/interview/note), tech docs mode (tutorial/API)
- **MCP Server** — AI clients (Claude / Cursor) can read and write content directly
- **GitHub Action** — zero-config CI entry (`yuelinghuashu/story-cli@v1`), one-click "Push → Build → Release" pipeline
- **Watch mode** — auto-rebuilds on file changes

## 🚀 Quick Start

```bash
# Create a demo repo and see it in action
story demo

# Initialize a repository
story init

# Create content and write
story new "My First Story"

# Build all READMEs
story build

# Export EPUB / stats
story epub --all
story stats
```

<details>
<summary>💡 Recommended: Use the Makefile workflow</summary>

```bash
make init                 # Initialize
make new TITLE="My Story"  # Create + auto-build
make commit               # Build + commit
make push                 # Build + commit + push
make stats                # Show writing statistics
```

Windows users can also use `story.ps1` generated by `story init`: `.\story.ps1 init` / `.\story.ps1 new -Title 'My Story'` / `.\story.ps1 build`.

</details>

## 🌱 Beyond Stories

**General-purpose content governance** — any text asset that can be "normalized" can be managed with the same workflow:

| Template Mode                | Content Types                   | Typical Use Cases                |
| :--------------------------- | :------------------------------ | :------------------------------- |
| `--template=story` (default) | Novel / Story                   | Original, fan fiction            |
| `--template=knowledge`       | Paper / Interview / Blog / Note | Knowledge base, research library |
| `--template=tech`            | Tutorial / API Doc / Changelog  | Tech blog, project docs          |

```bash
story init --template=knowledge
story init --template=tech
```

## 🤖 Let AI Manage Your Content Library

story-cli includes a built-in **MCP Server** — AI clients (Claude Desktop / Cursor / VSCode Copilot Chat) can read and write your content library directly. The AI can independently complete the full "create → write → build → stats" loop without any manual terminal commands.

> 💡 **Token economics**: MCP tools are designed from the ground up to reduce AI invocation costs. `scan_stories` compact-by-default output (~80-95% savings for browsing), `read_chapter` on-demand truncation (~95%+ savings for continuation), `stats` all data in one call (~99%) — every detail is engineered to lower Token consumption for your AI workflow.

| Capability | MCP Tools                        | Description                                                                     |
| ---------- | -------------------------------- | ------------------------------------------------------------------------------- |
| 📖 Browse  | `scan_stories` / `read_chapter`  | List stories, read chapters (on-demand loading & tail truncation, saves tokens) |
| ✍️ Write   | `write_chapter` / `create_story` | Create new stories, atomically write content                                    |
| ✅ Govern  | `build` / `validate`             | Actually execute README rebuild, validate config                                |
| 📊 Stats   | `stats`                          | Total words / chapters / series progress / health                               |

```bash
# Start MCP Server (run in your story repository root)
story mcp-server
```

> 💡 See [docs/mcp.en.md](docs/mcp.en.md) for detailed setup and examples.

## 🛠️ Common Commands

| Command                                                      | Description                                         |
| ------------------------------------------------------------ | --------------------------------------------------- |
| `story init [--template=story\|knowledge\|tech]`             | Initialize a repository (story/knowledge/tech mode) |
| `story new "Title" [--type] [--lang] [--author] [--creator]` | Create a new entry                                  |
| `story build [--validate-only] [--save-counts] [--watch]`    | Build READMEs                                       |
| `story epub "Title" [--all] [--split-by-volume]`             | Export EPUB                                         |
| `story export html / txt / json / md [--stdout]`             | Export formats                                      |
| `story import json --file=xxx.json`                          | Batch import from JSON                              |
| `story stats [--json]`                                       | Writing statistics                                  |
| `story mcp-server`                                           | Start MCP Server (AI connection entry)              |

<details>
<summary>Full command reference</summary>

| Command                                | Description                              |
| -------------------------------------- | ---------------------------------------- |
| `story init --full`                    | Also generate LICENSE / docs / CHANGELOG |
| `story build --save-counts`            | Persist auto word counts to config.json  |
| `story build --watch`                  | Watch for changes and auto-rebuild       |
| `story epub "Title" --split-by-volume` | Export as split volumes                  |
| `story export txt --stdout`            | Text stream output                       |
| `story export json --stdout`           | JSON stream output                       |
| `story export md --stdout`             | Markdown stream output                   |
| `story help` / `story version`         | Help / version                           |

**`story new` options**: `--type=original|fanfic` (default original), `--author="Work"` (required for fanfic), `--creator="Author"` (required for fanfic), `--lang=zh|en` (default zh).

</details>

<details>
<summary>Repository config (story.config.json)</summary>

Customize content types/statuses and localized labels:

```json
{
  "types": ["original", "fanfic", "translation"],
  "statuses": ["completed", "ongoing", "planned"],
  "typeLabels": { "translation": { "zh": "翻译", "en": "Translation" } }
}
```

Built-in enums don't need labels. Remove the file to fall back to defaults.

</details>
